# راهنمای کاربری

## پروژه و محیط

مدیر سیستم پروژه ایجاد می‌کند. مدیر پروژه نام، شرح و مسیر توصیفی vCenter را ویرایش و محیط‌های دلخواه ایجاد می‌کند. تغییر نام، شناسه روابط را عوض نمی‌کند. بایگانی به‌جای حذف استفاده می‌شود؛ API حذف پروژه/محیط/ماشین ارائه نمی‌کند. روابط مهم PROTECT هستند. دیسک فقط در ویرایش صریح یا تصمیم تأییدشده ورود حذف می‌شود و نسخه قبلی در تاریخچه باقی می‌ماند. پروژه بایگانی‌شده ویرایش موجودی و ورود را نمی‌پذیرد. محیط بایگانی‌شده در فرم انتخاب جدید نیست؛ سابقه آن باقی می‌ماند.

## موجودی

هر ستون مستقل است: Environment، Server Name، Application، VMs (نقش مانند Worker 1)، CPU/Core، RAM/GB، هر دیسک/GB، OS، Network/VLAN، IP، Subnet، Gateway، Username، کنترل رمز و وضعیت. دیسک غایب با — نمایش داده می‌شود. انتخاب Server Name آکاردئون همان ردیف را باز می‌کند. نام سرور هنگام پیمایش افقی ثابت است. زبانه مشخصات فرم گروه‌بندی‌شده با فیلدهای مستقل و زبانه فعالیت شامل نویسنده، زمان تهران، مبدأ، متن و مقدار قبلی/جدید است.

ویرایش شماره نسخه می‌خواهد؛ تغییر هم‌زمان خطای 409 می‌دهد. فرم قدیمی را پس از نگهداری تغییرات خود دوباره باز کنید. فرم ذخیره‌نشده هنگام بستن صفحه هشدار می‌دهد. حذف/افزودن/تغییر ظرفیت/ترتیب دیسک در تاریخچه ثبت می‌شود. رویدادهای تولیدی قابل ویرایش نیستند. نظر و کار انجام‌شده را نویسنده یا مدیر پروژه با کنترل نسخه و حفظ متن قبلی ویرایش می‌کند.

## ورود XLSX

۱. پروژه، فایل و Worksheet را انتخاب کنید. ۲. نگاشت ستون‌ها و ردیف عنوان را بررسی کنید. ۳. اعتبارسنجی را اجرا کنید. ۴. هر ردیف را جداگانه تأیید یا رد کنید. ۵. تطبیق و سیاست فیلدها/دیسک‌ها را انتخاب و تراکنش را اعمال کنید.

عنوان‌های نمونه: Row، Environment، Application، VMs، CPU (Core)، RAM (GB)، HDD (GB) تکراری یا Disk 1/HDD 3، OS، Network، ستون خالی، Server Name، Server IP Addr، Subnet (CIDR)، GW IP Addr، Username، Password. نگاشت صریح مستقل از موقعیت ستون است. سلول ادغام‌شده Environment/Application فقط در محدوده همان ادغام منتقل می‌شود. ردیف جداکننده ماشین نمی‌سازد.

ظرفیت مثبت دیسک می‌سازد؛ صفر/خالی دیسک نمی‌سازد؛ منفی، واحد متنی و بیش از دو رقم اعشار رد می‌شود. محدودیت هر ماشین ۶۴ دیسک است. OS ناشناخته حفظ و هشدار داده می‌شود. IP و Gateway معتبر باید هم‌نسخه باشند؛ Gateway بیرون Subnet هشدار دارد. Subnet می‌تواند /24، 24 یا 255.255.255.0 باشد و به /24 تبدیل می‌شود. مقدار خالی خالی می‌ماند؛ ماسک غیرپیوسته رد می‌شود. IPv6 و /128 نیز پشتیبانی می‌شود. IP تکراری در همان پروژه/محیط/شبکه هشدار است، شناسه نیست.

خروجی UUID ماشین و متادیتای شناسه/نام/ترتیب دیسک را در ستون‌های مخفی دارد. این ستون‌ها را حذف یا دستکاری نکنید. فایل بدون UUID فقط بر اساس نام دقیق و محیط، نامزد تطبیق ارائه می‌کند و **حتی یک نامزد نیز نیازمند انتخاب صریح است**. IP به‌تنهایی تطبیق نمی‌دهد. حالت فقط افزودن، به‌روزرسانی را رد می‌کند. می‌توانید ماشین جدید مستقل انتخاب کنید. رکورد غایب از فایل حذف نمی‌شود.

تعارض فیلدها را با Excel/وب یا به تفکیک فیلد حل کنید. سیاست دیسک: حفظ تمام دیسک‌های وب، ادغام ظرفیت ورودی با حفظ دیسک‌های اضافه، یا جایگزینی کامل و حذف صریح غایب‌ها. در فایل بدون متادیتا، دیسک به ترتیب فعلی نامزد جایگزینی می‌شود؛ قبل از تأیید پیش‌نمایش را بازبینی کنید. اگر نسخه هر ماشین هدف بعد از پیش‌نمایش عوض شود کل تراکنش رد می‌شود. فرمول، ماکرو، پیوند خارجی، فایل بزرگ و XML/ZIP خارج از حدود مجاز پذیرفته نمی‌شوند. XLS قدیمی پشتیبانی نمی‌شود.

## خروجی

داده جاری پایگاه داده، شامل ویرایش وب، صادر می‌شود. تعداد ستون دیسک به بیشترین تعداد واقعی انتخاب‌شده وابسته است؛ حداقل دو ستون برای سازگاری نمونه. گروه‌بندی محیط و ادغام اختیاری، ردیف جداکننده، Subnet مستقل و قالب‌بندی اعمال می‌شود. اگر فایل ورودی اصلی وجود دارد عنوان/ترتیب/عرض‌های آن مبناست؛ ستون‌های افزوده انتهای قالب اصلی درج می‌شوند. بدون فایل اصلی تقریب مستند نمونه تولید می‌شود؛ ادعای بازتولید دقیق تصویر نداریم. اشکال گرافیکی، نمودارها و همه styleهای سفارشی XLSX تضمین نمی‌شوند. مقادیر آغازشونده با =، +، -، @ برای جلوگیری از فرمول با apostrophe ایمن می‌شوند.

خروجی فعالیت شامل UUID، نام فعلی، نویسنده، زمان UTC قابل تبدیل، نوع، متن و تغییرات است. خروجی رمز انتخاب صریح و مجوز مستقل دارد و روی سرور ذخیره نمی‌شود. پس از لغو مجوز، درخواست تازه رد می‌شود؛ فایل قبلاً دانلودشده را سرور نمی‌تواند پس بگیرد.
