# دسترسی و امنیت

| نقش | اختیارات پروژه |
|---|---|
| Viewer | مشاهده موجودی و تاریخچه |
| Operator | مشاهده و نظر/کار انجام‌شده؛ خروجی فقط با مجوز export |
| Editor | افزودن/ویرایش ماشین و دیسک، فعالیت، خروجی معمولی |
| Project Manager | اختیارات Editor، پروژه/محیط، ورود و خروجی |
| System Administrator | مدیریت سیستم و تمام پروژه‌ها |

عضویت پروژه الزامی است؛ مجوز مستقل عمومی به‌تنهایی عضویت ایجاد نمی‌کند. هر کاربر می‌تواند در پروژه‌ها نقش متفاوت داشته باشد. مجوزهای مستقل: credential_view، credential_edit، credential_export، export، manage_users، auth_settings، audit_view، perform_updates. فقط مدیر سیستم می‌تواند مدیر سیستم دیگری بسازد؛ مدیر واگذارکننده مجوز نمی‌تواند مجوزی بالاتر از اختیار خود واگذار کند. آخرین مدیر فعال تحت قفل تراکنشی محافظت می‌شود. audit endpoint فقط خواندنی است. UI مرز امنیت نیست؛ query، ورود، خروجی و بازیابی راز مجوزسنجی می‌شوند.

حساب‌ها با الگوریتم استاندارد هش Django، اعتبارسنجی حداقل ۱۲ نویسه، جلسه HttpOnly، CSRF، SameSite و کوکی Secure در تولید حفاظت می‌شوند. جلسه به‌طور پیش‌فرض ۱ ساعت و با بسته‌شدن مرورگر منقضی می‌شود. سیاست جلسه جدید روی ورودهای بعدی اعمال می‌شود. حساب غیرفعال از authentication خارج می‌شود. پنج شکست متوالی برای یک نام کاربری تا ۱۵ دقیقه محدود می‌شود؛ در reverse proxy سازمان نیز rate limit بر اساس IP اضافه کنید. تنظیمات نمونه اعتماد به TLS proxy فقط در شبکه خصوصی Compose معتبر است؛ backend عمومی نشود.

رمز قابل‌بازیابی ماشین با Fernet (AES + HMAC authenticated encryption) و کلید جدا از دیتابیس رمز می‌شود. فایل اصلی ورود نیز رمز می‌شود. رمز از inventory API حذف است و فقط در درخواست POST مستقل با Cache-Control no-store بازیابی می‌شود. افشای مجاز پس از ۱۵ ثانیه یا خروج از بخش پاک می‌شود؛ کپی کنترل مستقل و fallback دستی دارد. Clipboard خارجی به‌صورت خودکار پاک نمی‌شود. تاریخچه و audit مقدار رمز ندارند. هیچ نمونه‌ای رمز واقعی ندارد. رمز را در متن نظرات وارد نکنید؛ اپلیکیشن متن انسانی را خودکار secret-scanning نمی‌کند.

کلید در `.env` حفاظت‌شده یا secret manager سازمان نگهداری شود؛ منبع سورس یا دیتابیس محل کلید نیست. پشتیبان حاوی کلید و فایل محرمانه است؛ آن را رمزگذاری‌شده و خارج از host ذخیره کنید. rotation باید ابتدا کلید قبلی را حفظ، داده‌های credential و import را با ابزار مهاجرت بازرمزگذاری و آزمون بازیابی کند؛ تغییر مستقیم CREDENTIAL_KEY داده قبلی را غیرقابل‌بازیابی می‌کند. ابزار rotation خودکار این نسخه ارائه نشده است. secret_reference ذخیره می‌شود ولی adapter خارجی هنوز پیکربندی نشده؛ endpoint ادعای بازیابی آن نمی‌کند.

OIDC boundary: از یک backend احراز هویت Django و نگاشت شناسه immutable provider به User استفاده کنید؛ session و permission model را حفظ کنید. provider و MFA هنوز integration آینده هستند و رابط ادعای فعال بودن ندارد.

بازیابی مدیر: در جلسه کنسول مجاز، `docker compose --env-file .env -f deploy/compose.prod.yml exec backend python backend/manage.py changepassword USERNAME`؛ رمز از prompt مخفی گرفته می‌شود. برای اولین مدیر از bootstrap_admin استفاده کنید. هیچ endpoint عمومی reset مدیر نداریم.

به‌روزرسانی: وب Docker socket ندارد؛ helper مستقل opt-in و مورداعتماد با عملیات ثابت فقط انتشار پایدار allowlisted و manifest امضاشده را می‌پذیرد. اجازه اجرای helper معادل اختیار استقرار است و باید جدا از سرویس وب بررسی شود. کلید خصوصی انتشار روی host برنامه نباشد. credential خواندن release از credential انتشار توسعه‌دهنده جداست و فقط از فایل حفاظت‌شده خوانده می‌شود.

وب state به‌روزرسانی را فقط read-only می‌بیند؛ قفل، maintenance، stage و backup فقط توسط helper تغییر می‌کنند. journalهای فاقد رمز خواندنی‌اند ولی backup و کلیدها root-only هستند.
